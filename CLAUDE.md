# Code Charmer

Premium digital engineering studio site (https://codecharmer.io). A **WordPress block theme + core plugin monorepo** — every section is a server-rendered Gutenberg block, converted from (and pixel-faithful to) the original static build.

## Architecture

- `wp-content/themes/codecharmer/` — block theme, presentation only: `theme.json` tokens, templates/parts, `assets/css/{global,rail}.css`, `assets/js/site.js` (header, reveals, instrumented-rail driver, contact form), self-hosted variable fonts.
- `wp-content/plugins/codecharmer-core/` — all logic: PSR-4 `CodeCharmer\Core\` engine (`Plugin` container + `Bootable` services), 26 blocks in `src/blocks/*` (block.json + edit.js + **render.php** + style.css, built with `@wordpress/scripts` into `build/`), `cc_project` CPT, REST inquiry endpoint, SEO tags, and the idempotent seeder (`wp codecharmer install`) fed by the brand layer in `data/*.php`.
- Engine-vs-brand split follows `~/gramo/docs/METHODOLOGY.md`. Content copy lives in `data/pages.php` (block grammar heredocs), never hardcoded in classes.

## Standards (hard requirement)

`composer run lint` — PHPCS with **WordPress-Core/Extra/Docs + WordPress-VIP-Go + PHPCompatibilityWP** (PHP 8.3, WP ≥6.8) — must exit 0. `npm run lint` (eslint + stylelint) and `npm run build` must pass. CI (`.github/workflows/ci.yml`) blocks on all three; PHPStan level 6 is advisory. Escape every render.php output; no direct DB, no uncached calls, no runtime filesystem writes.

## Local dev

`npm install && composer install`, then `npm run env:start` (wp-env, PHP 8.3) → activate theme+plugin → `npm run env:install-content`. Rebuild blocks with `npm run build`; `npm start` for watch mode.

## Deploy

Push to `master` → `.github/workflows/deploy.yml` (generated by `~/setup-vps-deploy.sh`, wordpress mode): builds blocks, rsyncs **only** the theme + plugin dirs to the VPS, activates, seeds once (`.wp-content-seeded` marker guards), flushes caches. WP core / wp-config / uploads are never touched.

## Design Context

Two root docs are the source of truth for all design/UX work — read them before touching UI:

- **[PRODUCT.md](PRODUCT.md)** — strategy: register (brand), platform (web), users, purpose, voice, anti-references, principles.
- **[DESIGN.md](DESIGN.md)** — visual system: dual-surface theme, cyan+ink OKLCH tokens, typography (Bricolage Grotesque / Hanken Grotesk / Geist Mono), spacing, motion, block inventory.

**Design principles:** (1) Practice what you preach — the site *is* the portfolio · (2) Show, don't tell · (3) Systems, not pages · (4) Clarity is the flex · (5) Clients own it.

**Voice:** calm confidence, short paragraphs, strong headlines, technical-but-accessible. Never use marketing clichés (cutting-edge, revolutionary, next-generation, best-in-class, game-changing).

## Design tooling

The **impeccable** skill drives design/UX work (`.claude/skills/impeccable/`). Common commands: `/impeccable shape <feature>` (plan), `/impeccable craft <feature>` (build), `/impeccable critique|audit|polish <target>`, `/impeccable live` (in-browser iteration).

## Environment

Requires **Node ≥20** (pinned via `.nvmrc`) and PHP 8.3 for tooling parity with the server (local phpcs runs on older PHP via `platform-check: false`). Run `nvm use` before npm commands.
